# Decisions log

Choices made where `scope.md` was silent or where a deviation was needed.

## Phase 1

Writing the few components needed directly on Radix keeps them on our semantic tokens and pill/square rules.                                                                                                     |

## Phase 2

| #   | Decision                                                                                                         | Why                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Editor JSON is converted to plain objects before every server call** (`plainJson`)                             | ProseMirror builds node `attrs` with a null prototype, which React's server-action serializer rejects. Without this, any heading, mention or numbered list failed to save. This also fixed a latent Phase 1 bug in task descriptions.                                                                                                                                                                                         |
| 2   | **Version snapshots store the _previous_ state, at most once per 5 minutes** (+ explicit "Save version"; max 50) | A bad editing session can always be rolled back to what the note was before it. Restore snapshots the current text first, so restoring is itself undoable.                                                                                                                                                                                                                                                                    |
| 3   | **Autosave is serialised and has a local safety net**                                                            | Saves never overlap. Pending edits flush on navigation and when the tab is hidden, and a copy is kept in `localStorage` until the server confirms. If a tab dies mid-save, the draft is recovered on next open. A browser "leave site?" warning shows only while a save is pending.                                                                                                                                           |
| 4   | **`@task` mention (in notes) links that task to the note; `[[note]]` mention (in tasks and notes) links notes**  | Selecting an `@task` calls the same bidirectional link as the picker (`linkedNoteIds` ↔ `linkedTaskIds`). In a task description `[[note]]` links that note to the task. In a note, `[[note]]` is a navigational link only. Removing a mention from the text does not unlink; use the Linked panels.                                                                                                                           |
| 5   | **Autosave does not revalidate server components**                                                               | Revalidating on every keystroke batch would re-render pages needlessly. The notes list is dynamic and refetches on navigation.                                                                                                                                                                                                                                                                                                |
| 6   | **Global search is regex-based, not a Mongo `$text` index**                                                      | `$text` can't do prefix matching ("onboard" → "Onboarding"), which matters for search-as-you-type. Every word must match the title or body; results are scored in code (title exact > prefix > contains > body; open tasks and pinned notes get a small boost). Highlights are returned as parts, never raw HTML. Measured under 300 ms on 5,000 documents in tests. Revisit with Atlas Search if data grows far beyond that. |
| 7   | **Global search is built on `cmdk` and is the base for the Phase 4 command palette**                             | `Ctrl/Cmd+K` and `/` open it today. Commands (navigate, create, toggle theme…) get added to the same dialog in Phase 4.                                                                                                                                                                                                                                                                                                       |
| 8   | **One app-wide task editor**                                                                                     | Tasks open from lists, search results and a note's linked panel through a single provider, so behaviour is identical everywhere.                                                                                                                                                                                                                                                                                              |
| 9   | **Notes list shows at most 200 notes, no cursor pagination yet**                                                 | Same reasoning as tasks (Phase 1 #11); handled in the Phase 5 performance pass.                                                                                                                                                                                                                                                                                                                                               |
| 10  | **Notes soft-delete is wired (with Undo) but there is no Trash screen yet**                                      | The Trash view ships in Phase 4. Deleted notes are hidden everywhere and can be restored via Undo meanwhile.                                                                                                                                                                                                                                                                                                                  |
| 11  | **Server action errors are logged server-side**                                                                  | Clients still only see a generic message; the log keeps the real cause for debugging.                                                                                                                                                                                                                                                                                                                                         |

## Phase 3

| #   | Decision                                                                                                                         | Why                                                                                                                                                                                                                                                                                                                                        |
| --- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | **Browser-only reminders: no cron, email, web-push or VAPID keys**                                                               | Requested. Removed `/api/cron/reminders`, Resend, `web-push`, `PushSubscription` and their env vars from `scope.md`. Trade-off: reminders can only fire while the app is open. Missed ones are summarised on next open.                                                                                                                    |
| 2   | **The 30-second check is local; the network is only used on real events**                                                        | The layout hands the scheduler the next 48h of reminders inside the request it already makes. The 30s tick (plus an exact timer for the next one) only compares clocks. The one server call is "claim" when a reminder fires. No polling. The list is refreshed on navigation, after edits, and on tab focus if it is over 10 minutes old. |
| 3   | **Claiming is an atomic conditional update** (`sentAt` unset -> set)                                                             | Several tabs/devices race; exactly one wins and shows the notification. Verified with concurrent claims. Other tabs on the same browser are also told via `BroadcastChannel`.                                                                                                                                                              |
| 4   | **Native notification only when the tab is not focused**                                                                         | A focused tab gets an in-app card with Done / Snooze / Open. A background tab gets a native notification through the service worker (needed for action buttons), limited to `Notification.maxActions`. More than 3 due at once, or all late, become one summary.                                                                           |
| 5   | **Service worker calls `/api/reminders/action`**                                                                                 | Workers can't call server actions. The route requires the session cookie, a same-origin `Origin`, valid input, and is rate limited. `sw.js` is served `no-cache` so updates land immediately.                                                                                                                                              |
| 6   | **Relative reminders move with the due date; snoozed and custom ones don't**                                                     | A snooze becomes a custom-time reminder. Changing the due date recomputes `offsetMin` reminders and re-arms them; ones that would land in the past are dropped.                                                                                                                                                                            |
| 7   | **Default reminders**: timed = user default (15 min), all-day = at work start                                                    | Only when the task gets its first due date and the user hasn't edited reminders (`remindersCustomized`). Past-due defaults are skipped.                                                                                                                                                                                                    |
| 8   | **Quiet hours hold reminders**                                                                                                   | They fire when quiet hours end, as a summary if several.                                                                                                                                                                                                                                                                                   |
| 9   | **Recurrence only supports simple rules** (daily/weekly/monthly/yearly, interval, weekdays) with the end date stored in `endsAt` | `COUNT` and `UNTIL` in the rule are rejected, because each occurrence is a separate task. Monthly on the 31st skips months without one (rrule behaviour).                                                                                                                                                                                  |
| 10  | **Spawn-next is idempotent**                                                                                                     | The completed task records `recurrenceSpawnedId` with a conditional update before the copy is created, so double clicks and races create exactly one. Reopening a task removes its untouched copy. Completing late jumps to the first occurrence after now, so no pile of past-due copies.                                                 |
| 11  | **Recurrence maths runs on wall-clock time in the user's timezone**                                                              | rrule is run on "floating" dates, so 9:00 stays 9:00 across daylight-saving changes (tested for New York in both directions).                                                                                                                                                                                                              |
| 12  | **Board order uses midpoints between neighbours**                                                                                | Dropping a card only needs its two neighbours; orders renumber if precision runs out. The same `order` field serves every grouping. Done shows only the last 14 days.                                                                                                                                                                      |
| 13  | **Board and calendar drags have non-drag alternatives**                                                                          | The card ⋮ menu (Move to, Move up/down) and keyboard lifting on both. On the calendar, the task editor also changes the date.                                                                                                                                                                                                              |
| 14  | **Calendar week/month grids are custom** (no calendar library)                                                                   | As specified. Week view is a list per day (no hour grid). On phones the month shows dots and an agenda for the selected day.                                                                                                                                                                                                               |
| 15  | **A calendar day chosen for a new task wins over a bare time, loses to a named day**                                             | "Dentist 4pm" on 25 Nov is 25 Nov 4pm; "Dentist tomorrow" stays tomorrow.                                                                                                                                                                                                                                                                  |
| 16  | **Task editor mounts inside the reminder provider**                                                                              | It needs reminder state; the provider needs to open tasks. State lives in `TaskEditorProvider`, rendering in `TaskEditorHost`.                                                                                                                                                                                                             |
| 17  | **Removed `User.dailyDigest` and `notificationPrefs.email/push`**                                                                | Replaced by `reminderPrefs`.                                                                                                                                                                                                                                                                                                               |
| 18  | **Known small gap**: lists compute "overdue" with the browser clock on first render                                              | A task that becomes overdue between the server render and hydration can cause a one-off hydration warning. Harmless; passing a server timestamp would remove it.                                                                                                                                                                           |

## Keyboard focus

| #   | Decision                                                                                                                                                             | Why                                                                                                                                                                                                                                                        |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **The focus ring is the darker brand green in light mode (`#007a4d`) and mint in dark mode** (token `--focus`)                                                       | Spec §5 says a 2px mint ring, but mint is only about 1.3:1 against white, which fails the 3:1 minimum for focus indicators. The darker green keeps the brand hue at 5.4:1; mint stays in dark mode (14:1). `--ring` (mint) is still the decorative colour. |
| 2   | **Text fields draw the ring inside their border** (inset), buttons and links outside (2px offset)                                                                    | Rings on fields at the edge of a dialog or panel were clipped or spilled over neighbours.                                                                                                                                                                  |
| 3   | **Composite controls show one ring on the whole control** (e.g. the board card, task rows), the note title uses an underline, the palette search is a bordered field | The ring should surround what you would call "the thing", not an inner button.                                                                                                                                                                             |
| 4   | **Focus rules live in `@layer base`**                                                                                                                                | Unlayered CSS always beats Tailwind's layered utilities, so `focus-visible:outline-none` overrides were silently ignored and a second ring stacked on top.                                                                                                 |
| 5   | **Dialogs never show a ring on their own box**, and closing one returns focus to the control you were on                                                             | Shortcut-opened dialogs (Q, Ctrl+K, ?) have no trigger, so focus used to drop to the page body and Tab restarted from the top. The last focused control outside any overlay is tracked and restored.                                                       |
| 6   | **Page scroll padding (7rem top, 5rem bottom) and `scroll-py` on scrolling panels**                                                                                  | Tabbing could leave the focused control under the sticky top bar, the timer strip or the mobile tab bar, or flush against a scroll edge where its ring is clipped.                                                                                         |
| 7   | **Verified by a scripted keyboard audit**: Tab through 19 pages and 8 overlays in light and dark (1,427 stops)                                                       | Checks every stop has a visible indicator, is not clipped by a container, has at least 3:1 contrast, and that focus enters, stays in and returns from each overlay. Zero findings.                                                                         |

## Phase 4

| #   | Decision                                                                                                                                                                                                 | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Convert to task** takes the selected lines, or the cursor's line, creates one task each (max 20) linked both ways, with `sourceNoteId` and the note's project, then appends a task mention to the line | The link is visible in the text and in the Linked tasks panel. Lines that already carry a task mention are skipped, so converting twice can't duplicate.                                                                                                                                                                                                                                                                                                 |
| 2   | **"Waiting on" is separate from status**                                                                                                                                                                 | A task can be in progress and waiting at once. A follow-up date does not fire a notification (it is a list, not a reminder). Overdue = before today; "today" is shown separately.                                                                                                                                                                                                                                                                        |
| 3   | **Daily review**: _completed_ = finished today; _still open_ = open and due today; _slipped_ = open and due before today                                                                                 | Reviewing at the end of the day means anything not done today has slipped. Carry over keeps the time of day.                                                                                                                                                                                                                                                                                                                                             |
| 4   | **Weekly completion rate** = tasks due that week that are done ÷ tasks due that week                                                                                                                     | A clear, honest ratio. "Completed" is counted separately (any due date). Time per project comes from time entries that _started_ in the week.                                                                                                                                                                                                                                                                                                            |
| 5   | **One timer at a time, stored on the user** (`activeTimer`), so it survives reloads and other devices                                                                                                    | Starting another logs and replaces the first. Sessions under 30 s are ignored, a forgotten stopwatch is capped at 12 h, and a Pomodoro work phase counts at most its 25 minutes. Only work is counted, not breaks. Completing or deleting a task stops its timer. Long breaks are not implemented.                                                                                                                                                       |
| 6   | **Templates have a third kind, `note`**, besides `task_checklist` and `meeting_note`                                                                                                                     | A regular note saved as a template shouldn't pretend to be a meeting note. Starters are created once per user with an atomic flag, so a deleted starter stays deleted. A checklist template creates one task with subtasks.                                                                                                                                                                                                                              |
| 7   | **Command palette filters commands on every keystroke; only the server search is debounced**                                                                                                             | Filtering on the debounced text made Enter run a stale selection.                                                                                                                                                                                                                                                                                                                                                                                        |
| 8   | **Shortcuts are ignored while typing or when a dialog is open**; `G` sequences expire after 1.2 s                                                                                                        | So letters can never navigate while you are writing. The sequence logic is pure and tested.                                                                                                                                                                                                                                                                                                                                                              |
| 9   | **Link titles: Jira/Confluence come from the URL (no network); other pages are fetched by the server with an SSRF guard**                                                                                | Only http(s), no credentials, max 10 links. The fetch refuses private/loopback/link-local addresses, checks IP-literal hosts explicitly (Node skips DNS for them), validates the address again inside the socket's own lookup (DNS rebinding), follows at most 3 redirects manually with the same checks, and times out at 4 s / 100 KB. A test caught the IP-literal gap. Favicons are loaded by the browser from the linked site's own `/favicon.ico`. |
| 10  | **Export never includes secrets**; CSV neutralises formula cells (`= + - @`)                                                                                                                             | JSON/CSV/Markdown are rate-limited, `no-store`, and per user. PDF uses the browser's print dialog with a print stylesheet that hides the app chrome.                                                                                                                                                                                                                                                                                                     |
| 11  | **No cron for the 30-day purge**                                                                                                                                                                         | The layout purges expired items at most once every 6 hours (the slot is claimed atomically), and the Trash page always purges first. Purging removes versions and every reference to the item, and only items already in the trash can be purged.                                                                                                                                                                                                        |
| 12  | **The service worker caches only static files and full HTML pages**, never the API or in-app navigation payloads                                                                                         | Next.js falls back to a normal page load when a soft navigation fails offline, and the worker answers that from the saved HTML. Prefetch payloads flooded the cache and evicted real pages, so they are excluded. Pages are saved by the app after you view them (≤ 1/min per page, max 40). In development the worker never caches, so hot reload keeps working.                                                                                        |
| 13  | **Signing out clears the offline cache and queue**                                                                                                                                                       | The sign-in page tells the worker to drop saved private pages and removes unsent changes, so a shared computer keeps nothing. Unsent offline changes are lost on sign-out.                                                                                                                                                                                                                                                                               |
| 14  | **Offline writes are limited to adding and completing tasks**                                                                                                                                            | Simple, order-safe operations. The last toggle of a task wins; rejected operations are dropped so they can't block the rest; "signed out" replays wait for the next sign-in. Notes already keep a local draft.                                                                                                                                                                                                                                           |
| 15  | **Mobile top bar shows only the logo mark under 480 px**                                                                                                                                                 | The bell, search, Add and theme buttons plus the wordmark overflowed a 375 px screen.                                                                                                                                                                                                                                                                                                                                                                    |
